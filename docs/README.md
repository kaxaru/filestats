# Документация

## RFC

Формат для крупных или необратимых изменений: смена источника данных, новый
внешний сервис, изменение схемы хранения, всё что трогает боевой путь. Для
обычной фичи RFC избыточен.

Ключевое отличие RFC от спеки — разделы **Alternatives**, **Migration** и
**Rollback**: спека отвечает «как реализуем», RFC — ещё и «почему именно так»
и «как отменим».

| RFC | Тема | Статус |
|---|---|---|
| [RFC-001](RFC-001-download-confirmation-order.md) | Порядок подтверждения скачивания | Implemented |
| [RFC-002](RFC-002-adaptive-pacing.md) | Подбор темпа запросов вслепую | Implemented |
| [RFC-003](RFC-003-run-pacing-measurements.md) | Перенос замеров темпа в схему хранения | Implemented |

## Почему именно эти три

Критерий отбора — цена ошибки, а не объём кода.

**RFC-001** описывает единственное необратимое действие в системе. Ошибка в
порядке шагов теряет файлы навсегда и делает это молча: каталог перестаёт
предлагать имя, у нас его нет, исключения не возникает.

**RFC-002** касается боевого пути целиком. Ошибка стоит получасовых блокировок
и растягивает обход втрое, а «правильное» значение неизвестно в принципе —
сервис свой лимит не публикует.

**RFC-003** меняет схему хранения и потребовал миграции. Поводом стала неверная
строка в логе: она сообщала 155 файлов при фактических 1234, потому что
счётчики жили в памяти процесса и обнулились при перезапуске контейнера.

Остальные решения на RFC не претендуют: они обратимы и локальны. Те из них,
что неочевидны и вызывают вопрос «почему не проще?», записаны в
[DECISIONS.md](DECISIONS.md) — коротко, с отвергнутыми вариантами и, главное,
с условием пересмотра.

## Журнал решений

[DECISIONS.md](DECISIONS.md) — формат легче RFC: решение, почему, что
отвергли, **когда пересмотреть**. Последнее поле и есть суть записи: у любого
компромисса есть условие, при котором он перестаёт быть верным, и без него
журнал превращается в оправдание статус-кво.

| | Решение |
|---|---|
| D-001 | Счётчики цифр — десять полей, а не `Counter` |
| D-002 | Императивный маппинг вместо декларативного |
| D-003 | Сессия на операцию плюс `merge`, а не долгая транзакция |
| D-004 | Выбор файлов — в адресе и `sessionStorage`, а не на сервере |
| D-005 | E2E против заглушки каталога, а не боевого API |

## Измерения

Числа во всех RFC взяты из боевых прогонов против каталога задания, а не
придуманы для иллюстрации.

| Прогон | Файлов | Длительность | Запросов | `429` | `403` | Темп |
|---|---|---|---|---|---|---|
| #1 (без инструментовки) | 1234 | 11:07 | ~630 | 1 | 0 | ~57/мин |
| #2 (с замерами) | 1234 | 10:49 | 763 | 12 | 0 | 70.5/мин |

Содержимое в обоих случаях: 1234 файла по 500 символов, суммарно 617 000 цифр —
сходится с заявленным форматом.

**Оценка границы лимита.** Каталог её не публикует, поэтому она выведена из
собственного трафика: после каждого отступа к интервалу 1.00 с (60 запросов в
минуту) отказы прекращались, а разгон ниже ~0.55 с (более 109 в минуту)
вызывал их стабильно. Двенадцать циклов «разогнались — получили отказ —
отступили» за один обход, ни одной блокировки. Это оценка по наблюдениям, а не
опубликованное значение, и в интерфейсе она подписана именно так.
